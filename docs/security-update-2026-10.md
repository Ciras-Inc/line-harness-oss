# 2026年10月のセキュリティ更新

## 変更内容

- 管理画面のNext.jsを、ロックファイル上の15.5.14から15.5.28へ更新する。
- package.jsonの下限を15.5.28にし、pnpm-lock.yamlを再生成する。
- Next.jsが使うsharpを0.35.5へ固定し、古いロック済みの画像処理ライブラリが再利用されるのを防ぐ。
- Worker、Cloudflareの設定、GitHub Actions、LIFFの読み込み先は変更しない。

このリポジトリは公開プログラムのforkです。Cirasの本番で使われているかどうかは未確認です。管理画面は静的出力（output: 'export'）の設定ですが、この設定だけで公開環境全体の安全性を確定することはできません。

## LIFFの確認結果と残作業

apps/worker/index.htmlは `https://static.line-scdn.net/liff/edge/2/sdk.js` を読み込みます。npmの@line/liffを固定する構成ではありません。

公式案内では2.20.0〜2.31.0が影響対象で、2.31.1以降が修正版です。2026年10月23日の確認では、上記配信元のスクリプトに2.31.2が含まれていました。配信元が更新済みでも、公開画面やキャッシュが同じ状態かは別に確認します。

1. 本番でこのリポジトリを使っているか、担当者が確認する。
2. 使っている場合は公開画面のSDK読み込み先を確認する。
3. 新しく開いた外部ブラウザーで、画面が使用している `liff.getVersion()` の結果が2.31.1以降か確認する。利用者のトークンやプロフィールを確認・保存する必要はない。
4. 固定版や同梱版を使う別の画面があれば、同じ修正版以降へ更新して再ビルド・再反映する。

## 反映前に確認すること

1. ビルドするPC・CIで `node --version` を確認する。今回のNode.js修正版は22.23.4、24.22.1、26.12.1で、それぞれ同じ系列の修正版以降を使う。検証ではNode.js 24.22.1を使用する。
2. deploy-worker.ymlはNode.js 22の系列を指定しているが、実行された修正番号は未確認。ワークフローの変更はこのPRに含めない。実際の実行環境を確認し、必要なら権限のある担当者が別の変更で修正版へ更新する。
3. pnpm 9.15.4で `pnpm install --frozen-lockfile` を行い、`pnpm --filter web exec tsc --noEmit` と `pnpm --filter web build` を実行する。
4. 管理画面の表示、通常ブラウザーとLINE内でのLIFF画面の表示を確認する。実際の配信、予約、登録処理は動作確認に含めない。
5. レビュー、検証、本番反映の承認がそろってから反映し、反映したコミットとビルド時のNode.jsの版を記録する。

## 更新候補の検証結果（2026年10月23日）

Node.js 24.22.1、pnpm 9.15.4で確認しました。

- frozen-lockfileによるインストール：成功。
- Webのtypecheck：成功。
- 本番ビルドと29ページの静的生成：成功。ビルドコマンドの間だけNEXT_PUBLIC_API_URLに検証用のhttp://127.0.0.1:8787を指定しました。本番の接続先設定や.envは使用していません。
- インストール先のNext.js：15.5.28。Next.jsが使用するsharp：0.35.5。
- 管理画面専用のtestスクリプトは定義されていません。

接続先未指定の最初のビルドは、既存のNEXT_PUBLIC_API_URL必須チェックで停止しました。検証用URLを指定したビルドの成功を、実際のAPI接続・認証・配信・本番LIFF画面の動作確認の代わりにはしません。実稼働の確認、独立レビュー、本番反映は残っています。
