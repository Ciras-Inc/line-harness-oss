# AIが依頼を完成させる作業手順

## 着手

「目的／今回の段階／完成条件／対象repo・版／全体への影響」を短く確認する。これが鳥の目。コマンド一覧の事前登録や、既に確定した事項の聞き直しには使わない。

AGENTS.md→00_CIRAS_POLICY.json→repo固有context/profile→対象配下の指示の順に必要な規則を確認する。既存の同版確認は再利用する。対象が違えばそのrepoの変更を止める。秘密を開かず、repo名・branch・PR等の非秘密情報で照合する。

## 作成・検証

依頼範囲の調査、コード・文書・下書き、通常のローカル検証、差分、修正、必要なレビュー資料まで完成させる。細部では虫の目で実物・固定版・検証を確かめる。依存更新や新しい不具合など状況が変われば魚の目で影響を確認し、鳥の目へ戻って優先順位を整える。

通常の可逆的なソース整理・生成物置換・自作の合成fixtureの清掃は依頼範囲で行える。本番データ・共有資産・保護設定・復元困難な破壊操作とは区別する。既存制御が拒否する操作を別経路で通さない。

push/PR/保存も共有・通知・公開preview・deploy・費用等の副作用を確認する。通常の操作は、同じ固定版の必要な検証/レビュー、有効な操作承認、実権限と既存の適格経路がそろい、副作用まで承認範囲内ならAIが実行する。未承認・不明の効果に依存する操作だけを保留し、完成物・差分・手順を用意する。初期設定・有効な保護の適用とrepo固有の本人専用操作は、条件がそろっても本人が実行する。

## レビューと区切り

repo固有の必要な正式レビューを維持する。既存許可の連携は共有範囲・実権限・費用内で使える。通常送信は、権限ある本人が宛先・確定本文・添付を特定した依頼の範囲で実行する。新たな共有範囲や接続は対象別承認を確認する。正式レビューの経路不足で他の通常作業を止めない。

変更箇所と直接影響に必要な検証を終えたら区切る。重大な新事実がなければ、合格範囲の全面再レビューを繰り返さない。形式的な合格のためにテスト・レビュー条件・保護を削らない。

## 実行・読戻しと本人への引継ぎ

通常の操作は条件がそろった同一版でAIが実行し、サービスの結果を読み戻す。本人承認だけを実権限や検証成功の代用にしない。結果不明は再送前に照合し、版変更・不合格・本人停止で該当操作を保留する。

初期設定・有効な保護の適用とrepo固有の本人専用操作には、OWNER_HANDOFF.mdの型を今回の事実で埋める。条件がそろえば「本人実行待ち」、不足があれば理由と残件だけを示す。本人操作後の非秘密の読戻しはAIが支援する。復旧・再deploy・再送にも同じ操作別条件を適用し、本人専用の実適用を代行しない。本人の停止は明示再開まで保持する。
