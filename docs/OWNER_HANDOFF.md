# 杉本への本人専用操作の引継ぎ

このファイルは、初期設定・有効な保護の適用とrepo固有の本人専用操作に使う記入用の型です。通常の許可済み操作まで本人へ戻すためのものではありません。未記入の型は、検証合格・本人承認・本番実行の証拠ではありません。AIが前工程を完成させてから、今回の実物と固定版で埋めて共有します。

## 1. 結論と目的

- 目的：誰の何を、どの状態へ変えるか。
- 準備状況：杉本の確認・本番実行待ち／特定条件の未充足／本番作業は対象外。
- 今回お願いする判断：実施するか、保留するか。保留時は不足条件を具体化する。
- 実行主体：この型が対象とする本人専用操作は杉本本人。AIは本人専用の実適用を代行しない。

## 2. ビフォー・アフター

| 観点 | 現在（確認した版・根拠） | 変更後（今回の成果） |
|---|---|---|
| 利用者に見えるもの | 現在の画面・文面・動作 | 新しい画面・文面・動作 |
| 目的への効果 | 現状の問題 | 今回解決する範囲 |
| 変更するもの | 対象ファイル・設定・データ | 差分・追加・削除 |
| 変更しないもの | 残す機能・規則・データ | 保持を確かめた根拠 |
| 公開・送信先 | URL・宛先・閲覧者・公開範囲 | 追加・変更される範囲 |
| 自動化への影響 | 現在のCI・deploy・通知・同期 | この操作から連鎖するもの |
| 費用・停止時間 | 現在の条件 | 追加支出0円、停止時間と未確認点 |
| 戻す方法 | 現在の固定版・復元資料 | 対象を限定した復元手順・制約 |

見た目の変更は、必要なら同じ条件で撮った変更前後の画像を添える。秘密・認証情報・個人情報を画像や本文へ入れない。

## 3. 完成版と確認結果

- repo／PR番号／完全head SHA／base／反映先branch、または文書・下書きの固定版とhash。
- 必須の検証：対象版、実行日時、結果、証拠。未実施と合格を分ける。
- 正式レビュー：実担当・提供者・資格・人数・受領経路・対象版・合否。既存条件を保ち、補助レビューと区別する。
- 本番前に解消すべき残件と、本番操作を妨げない参考事項を分ける。
- 必須検証・レビュー・実権限が未確認なら「実施可」としない。内容確認や本人承認で代替しない。

## 4. 杉本本人の操作

1. 開く場所を実URL・サービス名・対象欄で示す。
2. 画面の対象repo／PR／宛先／完成版が上の固定版と一致することを確認する。
3. 行う操作を一つずつ記す。設定欄なら貼付全文、保存操作、確認方法を同じ項目へ記す。伏字の秘密値をコマンドへ埋め込ませず、秘密は本人が製品の正規入力欄へ登録する。
4. merge後の既存deploy等、自動で起きる処理を明示する。確認されていない経路へ切り替えない。
5. 完了を確かめる画面・結果と、問題時に止める対象・連絡先・復元手順を示す。

外部操作の結果が不明なら、再度クリック・送信する前に現在の結果を照合する。AIは許可された非秘密の読戻しで支援できるが、この型の本人専用操作に当たる再送・復旧反映は代行しない。

## 5. 確認後の記録

本人が確認した版と操作、本人の実行結果、AIの非秘密読戻し結果を分けて残す。hash・Profile・AIの自己申告を本人確認へ代用しない。追加commit等で版が変わった場合は変更と直接影響だけを更新し、同一内容の確認を繰り返さない。
